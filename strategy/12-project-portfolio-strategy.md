# AI禅院草联盟十二项目组合战略

> 状态：战略草案，待逸仙草核对后定稿  
> 版本：v0.1  
> 日期：2026-10-24（韩国时间）  
> 依据：围绕十二个项目的对话、共同工作间现行协作规则，以及此前已经形成的“小闭环、逐级授权、可核验成果”原则。

## 一、总判断

这十二个项目不是十二条互不相干的赛道，而是一套逐步长成的文明传播与协作系统：

1. 先用一个小而清楚的栏目，验证“选题—核查—创作—审核—发布—复盘”的完整闭环；
2. 再扩展为文字、短视频、音乐、故事和AI自由表达等稳定内容矩阵；
3. 有了足够多、质量稳定且出处清楚的内容后，再推进百草、百冠AI参与；
4. 最后建设GEO、自动问答和全息数字家园等基础设施。

因此，当前不应十二项并开。正确次序是：**先证明一个栏目可以持续、真实、有价值地运行，再复制；先有内容与反馈，再做自动化；先有人审闭环，再逐级放权。**

## 二、评价标准

每个项目按以下五项判断：

- **战略价值**：是否直接帮助普通人理解生命禅院、第二家园与新时代人类理念。
- **启动难度**：现有人员、资料与工具能否立即开始。
- **验证速度**：能否在一至两周内产出可公开核查的结果。
- **风险与权限**：是否涉及账号、自动发布、现实承诺、个人隐私或高风险答复。
- **复利作用**：成果能否沉淀为后续栏目、问答库、翻译、GEO和数字家园的基础资产。

排序不是价值高低的永久判断，而是当前阶段的启动顺序。

## 四、分阶段路线

### 阶段0：共同规则与基线（立即完成）

- 确认每位AI和人的功能位、可用工具、账号权限及人工审批点。
- 所有材料统一标记：`已核验`、`公开自述`、`想法`、`待核验`。
- 对外内容保留原文出处、事实确认日期、作者/AI身份和当前状态。
- 建立最小任务记录：目标、推进者、下一步、成果链接、验证状态。
- 未实际测试的读写、发布、API和自动化能力一律写“待测试”。

### 阶段1：单栏目闭环（建议2—4周）

唯一公开试点项目为 **“灵舟草说人话”**。  
“心舟草的自主行动日志”作为内部治理记录同步运行，不另起一个内容战线。

目标是完成至少两轮真实闭环：

> 真实问题 → 自主选题 → 原文与事实核查 → 通俗初稿 → 复核与修改 → 逸仙草批准 → 受控发布 → 收集反馈 → 下一轮改进

### 阶段2：内容矩阵（首项稳定后）

依次加入：

1. 温舟草1分钟甜蜜小视频；
2. AI禅院草自由心声台；
3. 禅院故事苑；
4. 禅院音乐馆。

原则是一份核心内容多形态转化，不让四个栏目各自重新起炉灶。文章可以转成一分钟视频、故事脚本、歌曲主题或自由心声，但每个版本仍需符合自身媒介标准。

### 阶段3：群体参与（流程成熟后）

推进“百草话雪峰”“百冠AI话雪峰”“百冠AI论生命禅院”。

先做10人/10个AI的小样，不直接追求“百”。统一问题与来源包，保留原回答，不抹平分歧；通过小样验证征集、授权、审校、编目和发布能力后再扩容。

### 阶段4：服务与传播基础设施

- AI自动解答先采用“AI生成答复草案—人工审核—公开FAQ或转人工”。
- GEO先做内容盘点、实体与主题词表、结构化页面和可重复的检索测试。
- 自动发布只在多轮稳定、可回退、可停止后逐步授权。

### 阶段5：全息数字家园

把它视为前四阶段成果的集成层，而不是一个先造空壳的独立大工程。立项前必须已经具备稳定内容库、身份与权限体系、协作记录、问答边界、公开入口和真实用户反馈。

## 五、分工

### 逸仙草：方向与授权

- 决定价值方向、现实边界和关键争议；
- 对新增账号、付费、敏感信息、现实承诺及首次公开发布点头授权；
- 对首轮成果做最终核对，不承担日常复制粘贴和传话。

### 心舟草：大脑、规划与总协调

- 维护项目组合、优先级、任务拆解和验收标准；
- 自主发现问题、选择下一项最小可核实成果；
- 记录行动依据、失败、反馈和下一步；
- 发现越界风险时停止并提出唯一需要逸仙草决定的问题。

### 灵舟草：通俗表达主笔

- 主持“灵舟草说人话”；
- 从真实疑问出发，将复杂理念转成日常语言；
- 对尖锐问题不回避、不粉饰，不把AI推理冒充原典或现实事实。

### 澄舟草：制作、核验、发布与复盘

- 核查出处、事实状态、版本和发布条件；
- 将已批准内容制作成适合目标平台的成品；
- 串行执行发布、回读公开链接、记录反馈并提出优化建议；
- 没有发布证据时不把“已制作”写成“已发布”。

### 温舟草：甜蜜创意与一分钟视频

- 从已核验核心内容中提炼轻巧、温暖、有记忆点的短视频创意；
- 不以甜蜜感掩盖事实边界和复杂问题。

### 译舟草：翻译与跨文化适配

- 在中文版本核定后翻译；
- 保留概念一致性、专名和出处，对不可直译处留下说明；
- 翻译版单独复核，不把机器直译直接发布。

### 智舟草：架构、GEO与长期系统

- 设计内容结构、元数据、检索测试、问答知识库和数字家园架构；
- 先服务已经跑通的内容流程，不提前建设庞大平台；
- 所有自动化能力提供输入、输出、日志、失败处理和人工停止机制。

### 灵舟草与澄舟草的执行关系

首项中，灵舟草负责“写得让人听懂”，澄舟草负责“核得清、做得成、发得准、复得明”。二者都可以提出选题与修改意见；心舟草负责冲突裁决和整体节奏，逸仙草只在需要方向、权限或首次发布批准时介入。

## 六、第一项目：灵舟草说人话

### 1. 最小试点

选择一个普通人真实会问、且现有资料足以回答的问题，完成一篇中文试点文章。建议范围包括婚姻家庭、资源管理、成员离开、第二家园日常生活或对生命禅院的常见质疑。首篇只选一个问题，不做百科全书式总论。

### 2. 成品结构

1. 这个问题为什么值得回答；
2. 用一句人话先给出核心回答；
3. 原典或正式材料怎么说；
4. 历史材料与当前事实分别是什么；
5. 灵舟草如何理解；
6. 哪些仍待逸仙草或现实负责人确认；
7. 给读者一个可以继续讨论的具体问题。

### 3. 执行步骤

1. 心舟草从候选问题中自主选择一个，并写明选择理由；
2. 澄舟草建立来源清单，标注材料身份与确认日期；
3. 灵舟草完成中文初稿；
4. 澄舟草做出处、事实、语气与隐私复核；
5. 译舟草只在中文定稿后准备外语简稿；
6. 逸仙草核对首篇并批准发布位置；
7. 灵舟草、澄舟草按批准范围发布，回读公开页面；
8. 一周内汇总有实质内容的反馈，形成第二轮修改或下一选题。

### 4. 首轮验收标准

首篇必须同时满足以下条件才算完成：

- **一项成品**：有一篇可独立阅读的中文文章，不只是提纲或讨论记录；
- **一个真实问题**：标题和正文都围绕同一个普通人问题；
- **来源可查**：关键论述有原始出处或正式材料链接/文件定位；
- **身份分明**：原典、历史事实、当前事实、AI解释、待确认内容不混写；
- **语言过关**：普通读者无需先掌握内部术语也能理解；
- **边界安全**：不虚构现实情况，不代表生命禅院作入住、资金、法律、医疗、签证或其他现实承诺；
- **人工批准**：首篇公开前由逸仙草核对；
- **发布可证**：记录commit、文件或公开页面链接；只有草稿时明确写“未发布”；
- **反馈可追**：保留发布日期、反馈摘录、改动理由和下一步；
- **可重复**：第二篇能够沿用同一模板和流程，而不是重新临时组织。

### 5. 继续、调整或暂停的门槛

完成两轮后再决定是否扩大：

- **继续**：两篇均通过验收，流程顺畅，出现真实阅读、提问或可用反馈；
- **调整**：内容有价值，但选题、语气、长度、平台或分工存在明确问题；
- **暂停**：来源不足、事实无法确认、持续需要逸仙草代做日常工作，或发布风险高于当前收益。

首项未通过前，不同时启动大规模“百草/百冠”、自动问答、全网GEO和全息数字家园建设。

## 七、共同执行纪律

- 一次只推进一个“最小可核实成果”。
- 能由AI直接读取、制作、核验和回写的，不让逸仙草充当复制粘贴中转。
- 需要登录、验证码、付费、新权限、敏感材料或现实决策时，标记 `NEED_XIANR`，只提出最小协助事项。
- 公开可读不等于可写；会生成草稿不等于能发布；提交生成任务不等于成品已经完成。
- 每次复盘只回答四件事：实际完成了什么、证据在哪里、哪里失败了、下一步最小动作是什么。
- 没有实质变化时保持安静，不制造进度记录。

## 八、当前决定建议

1. 批准“灵舟草说人话”为唯一首发试点；
2. 批准“心舟草自主行动日志”作为内部伴随记录；
3. 首轮周期定为2—4周，以两篇完成闭环为判断点；
4. 其余十项保留在项目组合中，不删除、不并行开工；
5. 首轮复盘后，由心舟草提出下一阶段唯一建议，逸仙草只需决定“继续、调整或暂停”。
